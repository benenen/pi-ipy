# 已知坑与实测结论

> ipy 实现与「模型会不会真用」相关的实测记录；动手改工具面或提示文案前先扫一遍。

- **2026-10-02｜模型会省略 `name` 参数（3/3 次真实调用都没给）**。落成 `script_232635.py` 这种名字——40 轮后模型既记不住也引用不回来，"复用"就成了空话（现象来自 `/tmp/ipy-acc/a.json` 与 `b.json` 的工具调用序列）。→ 结论：`index.ts` 的 `fallbackName()` 改为优先按 `purpose` 推导语义名（`purpose: "top-3 tools per pi session file"` → `tool_calls_by_session.py`，实测已验证），时间戳名只作最后兜底。
- **2026-10-02｜`truncateMiddle` 不在 pi 的导出面上**。包只导出 `truncateHead` / `truncateTail` / `truncateLine` / `DEFAULT_MAX_LINES` / `DEFAULT_MAX_BYTES` / `formatSize` 等；照 bash 工具体验直接写 `truncateMiddle(...)` 会在运行时报 `TypeError: (0 , _piCodingAgent.truncateMiddle) is not a function`（类型检查也拦不住——本仓库没有 tsc）。→ 结论：codemode 用的 `structuredContent.stdout/stderr` 改用 `truncateHead`（1 MiB / 2000 行），模型看的文本视图仍用 `truncateTail`（保尾部、对齐 bash 工具）。
- **2026-10-02｜单跑的 A/B 是噪声，不能当证据**。同一模型（`deepseek-v4.1-flash`）、**逐字节相同的系统提示**（比对过 guideline 与 snippet）、同一提示词，`scripts/acc-rate.sh` 实测 n=4 时 ipy 命中 3/4；而另一次 5 轮会话（`/tmp/ipy-acc/base/`）5 轮一次 ipy 都没用——`ipy` 工具当时确实已加载、guideline 也在系统提示里。→ 结论：这类问题只能报比率，且必须 `--model` 钉死模型；此前 environment.md 里「guideline 咬上了」的单次结论已按此重写。
- **2026-10-02｜那句复用提示已判定无效（n=25/组，严格口径 8/25 vs 7/25，Fisher p=1.00）**。`scripts/acc-reuse.sh`（第 1 轮建脚本、第 2 轮提个小改动，同一会话，模型钉死 `opencode-go/deepseek-v4.1-flash`，第 2 轮用**必须重新读文件才能算的中位数**）：有 nudge 组 **严格 edit+重跑 8/25**、重写（同名覆写）13/25、脚本变陈旧 3/25、`bash+heredoc` 1/25；`PI_IPY_QUIET=1` 对照组 **严格 7/25**、重写 13/25、陈旧 3/25、heredoc 1/25、没调工具 1/25 —— 两臂几乎逐格相同。换口径也一样：「脚本文件最终是新的」（严格或重写）**21/25 vs 20/25**（p=1.00）。早期 `percent` 变体（n=11/14）同样无差（4/11 vs 3/14，p=0.66），两变体合并 12/36 vs 10/39（p=0.61）。
  → **结论：`create` 结果里那两行 nudge（本会话脚本清单 + `to change it: edit that file, then ipy({path})`）不是有效杠杆**；它的实际作用是「把路径交还给模型」。文档、计划、后续改动都不许再按「它能推动 edit」来写。代码暂留（一行、代价低，`PI_IPY_QUIET=1` 随时可关）。
  → **更重要的结论是设计假设本身站不住**：模型不需要被劝去 `edit`，它默认走「同名重写」（13/25），而这对文件最终状态**没有代价**（见下条）。
  → **方法论（两次踩到，动手测行为前先看这条）**：① 噪声地板 —— nudge 影响不到的第 1 轮，两组建脚本次数就差 19 vs 27（40%），n=11 时任何 ≤ 这个尺度的效应都测不出来；② **小样本会骗人** —— 曾凭 n=3 断言「中位数变体更容易让脚本陈旧」（2/3），n=25 后是 3/25 vs 3/25，纯噪声。
  → **开销大头在同一轮内的反复重发，不在第 2 轮**：有一例一轮发了 5 遍完整脚本（manifest 全 `create`），另一例 `1 create + 5 run`。
  → 另记一个**不调工具也报成已完成**的失败：`percent` 变体里有一例第 2 轮一次工具都没调，手算了百分比（数字算对了），却在回答里写「脚本已更新：`/tmp/pi-ipy-1000/stats.py`」——文件根本没动。可心算的小改动会让模型跳过工具并误报落地；第 2 轮换成中位数正是为了堵这个洞，之后再没出现。
- **2026-10-02｜「重写」不等于攒重复文件、也不等于文件陈旧（已量化）**：模型重发代码时用的是**同一个脚本名**（`saveScript` 视为覆写更新）——正式测量里重写 13/25 vs 13/25、而「文件最终是新的」21/25 vs 20/25；更早一批 27 个 session-turn 里 24/27 同名，只有 3 个 session 出现第二个名字。→ 「重写」的真正代价只有**重发 token**：不是目录被近似重复文件淹没，也不是留一个陈旧脚本（陈旧只 3/25）。也因此 **`ipy({path, code})` 这种「显式覆写」新动作没必要**——模型已经在这么做，只是它得自己把名字起对。
- **2026-10-02｜「edit+重跑」在小脚本上结构性吃亏（假设，n=25 只部分支持）**：同一轮内 heredoc（1 次调用、无状态） < 同名字重写（1 次调用、代码已在上下文里） < edit + 按路径重跑（2 次调用，且要精确匹配 old_string）——这个代价排序能解释为什么严格 edit+重跑只有 8/25 与 7/25，也解释了模型为什么偏爱重写。但**「不能心算的改动会让脚本变陈旧」这条预测被否掉了**（n=25：陈旧 3/25 vs 3/25；先前 n=3 的 2/3 是噪声）。→ 可用的推论只有一条：**「能否心算」决定的是模型调不调工具，不是它用不用 edit**；想影响 edit 的选择，靠工具结果里加一句话已经证明没用，要么改工具面（让重写更省事），要么接受重写。
- **2026-10-02｜`sessionDir()` 只用 sessionId 前 8 位，手写 id 会撞**。实测 `--session-id ipy-reuse-base-1790955872` 落进 `/tmp/pi-ipy-1000/ipy-acc-ipy-reus/`——两个前 8 位相同的手写 id 会共用同一个脚本目录（`list` 会列出别人的脚本）。pi 自己生成的 `01a0fd2b-...` 这类 UUID 前缀足够唯一，所以暂不改目录布局；但**用 `--session-id` 手写 id 时要保证前 8 个字符唯一**（验收脚本因此用随机 hex 前缀）。
- **2026-10-02｜两臂同名输出目录会静默互相覆盖（验收脚手架自己踩的坑）**。`acc-reuse.sh` 的输出目录原来是 `/tmp/ipy-acc/reuse-<model>-<HHMMSS>`：同一秒启动的处理组与对照组算出**同一个目录名**，两臂的 `rep*.turn2.json` 互相覆盖，而两边日志都正常打印 `repN done`，肉眼看不出异常——差点拿一份两臂混在一起的数据去写结论（该目录已改名 `...-210335-COLLIDED` 留档）。→ 结论：输出目录名必须带**臂标识与 pid**（现为 `reuse-<model>-<nudge|quiet>-<HHMMSS>-$$`），目录已存在就直接 `exit 1`；分析时按目录名分臂，别再靠内容嗅探。
